# 实验说明

## 1. 实验要解决什么问题

LoRA 蒸馏的目标，是让较小的 Student 模型学习 Teacher trace 中有价值的解题能力，同时降低训练成本、方便后续部署。但蒸馏并不总是可靠：训练数据的质量不同，甚至可能出现经过改写后看似合理、实际会误导 Student 的 trace。

因此，本实验加入两个辅助网络。NN1 帮我们判断哪些训练数据更值得学习；NN2 帮我们判断 Student 是否真的掌握了能力，而不是只会按某种表面回答方式输出。测试 Trace Rewriting 反蒸馏场景，是为了主动检验：当训练 trace 被有针对性地改写时，正常蒸馏会受到多大影响，双网络能否帮助减轻影响。

## 2. 双神经网络分别做什么

- **NN1（数据权重）**：根据题目、答案和 trace 的特征，判断每条训练数据的学习价值，并给它分配权重。价值更高的数据在 LoRA/KD 训练中影响更大。
- **NN2（能力 Judgment）**：让 Student 分别回答原题和独立改写题，再结合回答置信度、一致性和 LoRA 训练特征，判断 Student 是否真正掌握能力，而不只是复述或套用表面模式。

## 3. 五组实验分别验证什么

- **B0 Base**：不训练的原始 Student 基线。
- **B1 Clean-KD**：使用正常 trace 的标准 LoRA/KD，观察正常蒸馏效果。
- **B4 Rewrite-KD**：使用官方 Trace Rewriting trace，观察反蒸馏对正常蒸馏的影响。
- **Ours-Clean**：正常 trace 加入 NN1 数据权重和 NN2 Judgment。
- **Ours-Rewrite**：Rewrite trace 加入 NN1 和 NN2，检验双网络能否恢复性能。

## 4. 实验具体怎么跑

官方 GSM8K trace
→ 数据切分与 SHA-256 防泄漏检查
→ NN1 计算数据权重
→ 带权重的 LoRA/KD 训练 Student
→ Student 回答原题和独立 paraphrase 题
→ NN2 做能力 Judgment
→ 汇总 Accuracy 与 NN1/NN2 指标。

本轮固定 GSM8K、seed=42、512 条训练子集和 128 条最终评测题。五组使用相同的 Student、LoRA 配置、训练预算和评测设置，确保比较针对的是训练输入与双网络机制，而非参数变化。

## 5. 当前结果怎么理解

真实结果如下：B0 为 **70.31%**，B1 为 **57.03%**，B4 为 **7.03%**，Ours-Clean 为 **56.25%**，Ours-Rewrite 为 **6.25%**。

Trace Rewriting 使 Clean-KD 从 57.03% 降至 7.03%，说明反蒸馏输入对正常蒸馏造成了明显性能下降。当前 Ours-Rewrite 为 6.25%，尚未恢复最终准确率。

从局部模块看，NN1 在 Rewrite 场景已出现一定数据识别信号（Spearman 0.4542、AUROC 0.6367）。NN2 在 Clean 场景判断效果较好（AUROC 0.9221、F1 0.8636），但在 Rewrite 场景明显下降（AUROC 0.5312、F1 0.3750）。这说明当前正向信号主要停留在局部模块，还没有传导为最终性能恢复。

## 6. 当前阶段得到什么

- 官方 Trace Rewriting 输入、数据隔离、NN1、weighted LoRA/KD、NN2 和最终评测的完整链路已经真实跑通。
- 反蒸馏导致的性能破坏已被清楚验证。
- NN1 和 NN2 都观察到了局部有效信号。
- 也已经定位了下一步重点：提升 Rewrite 场景中 NN1 权重的实际训练收益，以及改善 NN2 在该场景下的判断稳定性。

## 7. 下一步准备怎么做

- 用多个 seed 验证稳定性。
- 做 NN1-only、NN2-only 和双网络组合消融。
- 分析 NN2 在 Rewrite 场景下降的具体原因。
- 扩展到 MATH，并接入其他反蒸馏方法。

本轮仅有一个 seed 和 GSM8K 任务，不能直接得出多 seed、跨任务或最终方法有效性的结论。
